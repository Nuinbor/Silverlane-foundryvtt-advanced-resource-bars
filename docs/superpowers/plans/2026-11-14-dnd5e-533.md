# D&D5e 5.3.3 compatibility implementation plan

**Goal:** Keep all resource tracking and automation available on D&D5e 5.3.3 without requiring a system upgrade.

**Architecture:** One module supports Foundry 13.347+ and 14, D&D5e 5.3.3+. Choose effect serialization by Foundry generation; detect native attack-message formats by their fields. Keep existing Actor flags and resource definitions unchanged.

**Evidence:** Upstream `release-5.3.3`, commit `965ad2d0cf5d063dac675ba078b5bd3c3c0dd449`. `system.json` supports Foundry 13.347 and 14. `module/documents/chat-message.mjs` reads `flags.dnd5e.roll.type` and `flags.dnd5e.targets` ({uuid, ac}); D20Roll exposes isCritical/isFumble. `module/documents/activity/mixin.mjs` snapshots targets at roll time. `CONFIG.ActiveEffect.documentClass` selects the system implementation. Foundry 13 uses top-level changes with numeric mode and duration.seconds/startTime; 14 uses system.changes and native duration/start.

**Constraints:** Preserve v14 / D&D5e 6.1 behavior, permissions, event deduplication, synthetic Actors, threshold history and recurring paralysis. No required third-party modules. No inference from current targets or unknown AC.

**Review focus:** Natural 1/20 against snapshot AC; missing/null AC; empty modern target lists; system status payloads on both core generations; max reset after a legacy monster hit.
