# Silverlane Advanced Resource Bars

Кастомные шкалы ресурсов, пороговые дебаффы и автоматизация атак для **Foundry VTT 14.367+ / D&D5e 6.1+**. Не требует Midi-QOL, DAE, libWrapper или socketlib. Интерфейс на русском и английском.

## Возможности

- Любое количество шкал до 40: название, максимум, цвет, описание и пороги.
- Компактное окно для одного или нескольких персонажей: ввод числа, ±1/±5, подсказки на отметках и история достигнутых порогов.
- Эффекты порогов: системный статус, произвольные изменения `system.*` через Active Effect, длительность, постоянный или зависящий от текущего значения дебафф.
- Сброс шкалы на максимуме, сохранение истории и отдельных эффектов после обнуления.
- Дополнительные полосы над своими токенами: до шести, без замены штатных HP. По умолчанию только у выбранных токенов.
- Правила на предметах/атаках монстров: прибавить ресурс при попадании, при применении урона или вручную. Можно ограничить правило конкретной активностью D&D5e.
- Значения хранятся на Actor; несвязанные токены используют свой синтетический Actor.

## Установка

До публикации первого Release используйте ручную установку или артефакт GitHub Actions:

1. Скачайте `silverlane-resource-bars.zip` из артефактов последней успешной проверки во вкладке Actions (нужен вход в GitHub) либо соберите его локально командами ниже.
2. Распакуйте содержимое установочного ZIP в `Data/modules/silverlane-resource-bars/`. Файл `module.json` должен лежать непосредственно в этой папке. Артефакт Actions содержит установочный ZIP внутри внешнего архива артефакта.
3. Перезапустите Foundry и включите модуль в мире D&D5e.

После публикации Release модуль можно установить по Manifest URL:

```text
https://github.com/Nuinbor/Silverlane-foundryvtt-advanced-resource-bars/releases/latest/download/module.json
```

Репозиторий сам по себе не создаёт Release. Workflow `release.yml` собирает и публикует его при пуше тега `v0.1.0` (версия тега должна совпадать с `module.json` и `package.json`).

## Быстрый старт

Создайте макрос типа **Script** и поместите его на панель:

```js
await game.modules.get("silverlane-resource-bars").api.open();
```

Выберите свой токен и запустите макрос. Также доступны **Alt+R** (переназначается в управлении) и кнопка с полосками в заголовке листа Actor. Без выбранного токена используется назначенный пользователю персонаж. Кнопка обновления в трекере переключает его на текущий выбор.

Настройка шкал: **Настройки игры → Настройки модулей → Silverlane Advanced Resource Bars → Настройка шкал ресурсов**, либо кнопка настроек в трекере (только мастер).

### Готовый пример: «Поражение нервов»

Шкала `nerve-damage` уже включена в настройки мира:

- Максимум **100**, обнуление при достижении максимума.
- На **20** — «Нервный тремор»: отметка с описанием и запоминанием достижения. По умолчанию это только предупреждение; конкретный механический штраф задаёт мастер.
- На **100** — системный статус **Paralyzed**, затем значение становится **0**. Создаётся системный Active Effect, а не просто значок.

Чтобы добавить на 20 штраф КД −2, откройте этот порог и вставьте в «изменения Active Effect»:

```json
[{ "key": "system.attributes.ac.bonus", "mode": 2, "value": "-2" }]
```

Можно одновременно выбрать статус и добавить собственные изменения. Сложные системные поля и режим `CUSTOM` имеют смысл только если сама D&D5e поддерживает соответствующую механику; модуль не исполняет JavaScript из настроек.

### «При попадании: +5 к поражению нервов»

1. Откройте лист монстра и **его собственный предмет атаки**, например укус. Правило на предмет в каталоге не меняет уже скопированные предметы монстров.
2. Нажмите кнопку с полосками в заголовке листа предмета. Альтернатива для мастера:

   ```js
   await game.modules.get("silverlane-resource-bars").api.configureItem(
     canvas.tokens.controlled[0].actor.items.getName("Укус")
   );
   ```

3. Добавьте правило: «Поражение нервов», изменение **5**, «При подтверждённом попадании». При необходимости выберите конкретную активность.
4. Перед броском **отметьте цель Foundry**. После броска атаки D&D5e модуль берёт результаты попадания из карточки атаки и увеличивает шкалу попавших целей. Промахи и цели без определённого КД не учитываются.

Автоматические попадания обрабатывает один активный GM. Если мастера нет в сети, автор броска может изменить только принадлежащие ему цели. Другие игроки не получают права записи в чужих Actor. Для атаки монстра по персонажу держите мастера подключённым.

«При нанесении урона» — отдельный режим: прибавка происходит после положительного `dnd5e.applyDamage` с исходной карточкой чата. Изменение HP вручную, лечение, нулевой урон и урон без ссылки на предмет не подходят. Урон в temp HP учитывается, если D&D5e сообщает положительный урон. Повторное применение одной карточки к одному Actor не начисляет ресурс повторно; новый бросок должен иметь новую карточку.

При активном **Midi-QOL** нативная обработка попаданий отключается, вместо неё используются `midi-qol.RollComplete` и `hitTargets`. Совместимость зависит от версии Midi-QOL; его установка не обязательна. Режим урона опирается именно на нативный `applyDamage`; для рабочих процессов других модулей используйте режим попадания или API.

## Правила порогов

- Порог включается на точном значении и при перескоке через него. Все достигнутые пороги записываются в историю.
- **Постоянный**: накладывается один раз до лечения; снижение шкалы не снимает эффект. Ручное снятие или истечение длительности не стирает историю и не накладывает его заново. Для нового срабатывания используйте лечение.
- **По текущему значению**: снимается при падении ниже порога и может включиться при следующем пересечении. На сбросе максимальный порог — исключение: его эффект сохраняется, чтобы паралич не исчезал сразу после наложения.
- При 95 → 105 максимум даёт **ровно 0**, не 5. Одно изменение вызывает не больше одного сброса.
- **В ноль**: сбрасывает число, сохраняет историю и постоянные эффекты. Эффекты текущего значения ниже порога снимаются.
- **Лечение**: обнуляет число, историю и счётчик перегрузок, удаляет только эффекты этой шкалы. Чужие статусы с тем же названием не трогаются.
- Отключение шкалы галочкой приостанавливает её изменение и отображение на токене, но не лечит персонажа.
- Изменения описаний порогов не переписывают уже созданные эффекты. Перед удалением шкалы или порога сначала вылечите затронутых персонажей; оставшиеся эффекты также можно снять в обычном листе Actor.

## API и макросы

```js
const bars = game.modules.get("silverlane-resource-bars").api;

await bars.open();                            // Выбранные свои токены / свой персонаж
await bars.open(token.actor);                 // Конкретный Actor или UUID
await bars.open([actor1, actor2]);             // Несколько Actor
bars.configure();                            // Редактор определений, только GM
await bars.configureItem(item);               // Редактор правил предмета, только GM

bars.get(token.actor);                        // [{ definition, state }]
bars.definitions();                           // Копия определений мира
await bars.adjust(token.actor, "nerve-damage", 5);
await bars.set(token.document.uuid, "nerve-damage", 70);
await bars.reset(token.actor, "nerve-damage");
await bars.reset(token.actor, "nerve-damage", { clearHistory: true });
await bars.setEnabled(token.actor, "nerve-damage", false);

// Явное подтверждение попадания для собственного workflow.
// Не вызывайте дополнительно к уже работающей автоматизации того же броска.
await bars.applyOnHit(item, [...game.user.targets], {
  activityId: "ACTIVITY_ID",                   // Для правил с фильтром активности
  eventId: "my-workflow:unique-attack-id"       // Необязательный ключ защиты от повтора
});

// Правила с режимом «только вручную»:
await bars.applyItem(item, [...game.user.targets], { trigger: "manual" });
```

Все операции записи асинхронны; используйте `await`. Actor, TokenDocument, Token и их UUID поддерживаются. UUID несвязанного токена сохраняет его отдельные значения. Для записи нужны права владельца цели или мастера; API не обходит права через сокеты. Состояние хранится в `flags.silverlane-resource-bars.resources`, правила предмета — `flags.silverlane-resource-bars.attackRules`.

Макросы в готовом виде находятся в `macros/`.

## Разработка и проверка

Node.js 22+ (CI использует 24):

```sh
npm ci
npm test
npm run check
npm run build
```

Установочный архив: `dist/silverlane-resource-bars.zip`; манифест для Release: `dist/module.json`. В архив не входят зависимости разработки, тесты и `.git`. Для запуска в Foundry сборка и Node.js не требуются.

Автотесты покрывают переходы порогов, эффекты, права, синтетических Actor, защиту от повторных событий, адаптеры D&D5e/Midi, шаблоны, формы, приватность полос и установочный ZIP. Они используют узкие имитации API Foundry, а не лицензированный сервер. Перед игрой проверьте в тестовом мире: +5 при попадании/отсутствие прибавки при промахе, 95 → 100 → Paralyzed + 0, лечение и разные значения двух несвязанных токенов.

Изменения сериализуются для одного Actor внутри клиента. Одновременные ручные записи в одного Actor с разных клиентов не являются распределённой транзакцией; не редактируйте одну шкалу одновременно с двух устройств.

## English summary

Standalone Foundry v14.367+ / D&D5e 6.1+ resource tracker. Create a Script macro containing `await game.modules.get("silverlane-resource-bars").api.open();`, or press Alt+R. GMs configure world resources through module settings and attack rules through the Item sheet header button. The default nerve damage bar warns at 20 and applies Paralyzed/reset-to-zero at 100. Gold ticks record previous threshold crossings. “Zero” preserves sticky effects/history; “Treat” removes only this resource's effects and history. Native hits require targeted tokens and a connected GM for foreign-Actor writes. Midi-QOL is optional. Install a release ZIP into `Data/modules/silverlane-resource-bars/`; before the first release use the Actions artifact or `npm ci && npm run build`.
